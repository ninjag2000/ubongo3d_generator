# ТЗ для Codex: добавить реальные детали Ubongo 3D из Thingiverse 6534722

Источник: https://www.thingiverse.com/thing:6534722/files

По поисковой выдаче объект называется **UBONGO 3D by PegFranck**, опубликован 2024-03-16, лицензия **Creative Commons Attribution / CC BY**. На странице файлов видны STL вида `JAUNE_3_UBONGO.stl` и `JAUNE_1_UBONGO.stl`. Полный список нужно брать с самой страницы Thingiverse или через скачанный ZIP.

## Цель

Заменить демонстрационную библиотеку деталей в генераторе на реальные polycube-координаты из STL-файлов Thingiverse.

Генератор должен работать так:

1. Пользователь открывает `index.html`.
2. В библиотеке деталей уже выбрана реальная библиотека `thingiverse_6534722`.
3. Можно генерировать карточку с настройками:
   - `pieceCount` — сколько деталей в одной комбинации;
   - `levels` — сколько уровней в высоту;
   - `comboCount` — 6 комбинаций на одно поле.
4. Каждая из 6 комбинаций должна решать один и тот же 3D-объём.

## Важное правило

Не рисовать детали вручную и не придумывать формы по картинке. Нужно получить форму из STL, привести её к сетке маленьких кубиков и сохранить как JSON.

## Шаг 1. Скачать файлы

Скачать все STL из Thingiverse 6534722 в папку:

```text
source_stl/thingiverse_6534722/
```

Ожидаемые имена, которые надо проверить по фактическому ZIP:

```text
JAUNE_1_UBONGO.stl
JAUNE_2_UBONGO.stl
JAUNE_3_UBONGO.stl
...
ROUGE_1_UBONGO.stl
BLEU_1_UBONGO.stl
VERT_1_UBONGO.stl
```

Если цвета/номера отличаются — ориентироваться на реальные файлы, а не на этот пример.

## Шаг 2. Конвертировать STL в polycube JSON

Запустить:

```bash
python tools/stl_to_pieces_json.py source_stl/thingiverse_6534722 data/pieces_thingiverse_6534722.json
```

Скрипт должен:

1. Прочитать каждый STL.
2. Найти размер одного кубика детали.
3. Вокселизировать модель или восстановить кубики по bounding boxes.
4. Нормализовать координаты так, чтобы минимум по x/y/z был `[0,0,0]`.
5. Схлопнуть одинаковые формы разных цветов в одну уникальную форму, если геометрия совпадает.
6. Сохранить JSON вида:

```json
[
  {"id":"P01","sourceFiles":["JAUNE_1_UBONGO.stl"],"cubes":[[0,0,0],[1,0,0],[0,1,0]]}
]
```

## Шаг 3. Проверка качества

После конвертации обязательно вывести отчёт:

```text
Loaded STL files: N
Unique shapes: M
Piece P01: volume 3 cubes, dims 2×2×1, files: ...
Piece P02: volume 4 cubes, dims ...
```

Проверить:

- нет ли пустых деталей;
- нет ли деталей с дробными/съехавшими координатами;
- одинаковые детали разных цветов действительно схлопнулись;
- если зеркальные формы в игре считаются разными, НЕ схлопывать зеркала; схлопывать только совпадающие после вращения без отражения.

## Шаг 4. Подключить библиотеку в генератор

В `app.js` заменить `DEFAULT_PIECES` на загрузку из `data/pieces_thingiverse_6534722.json`.

Так как локальный браузер может блокировать `fetch()` для `file://`, сделать fallback:

1. Попробовать `fetch('data/pieces_thingiverse_6534722.json')`.
2. Если не получилось — использовать встроенную демо-библиотеку и показать предупреждение.
3. Добавить кнопку "Загрузить pieces.json" через `<input type="file">`, чтобы пользователь мог вручную выбрать JSON.

## Шаг 5. Улучшить UI карточки

На карточке рядом с каждой из 6 строк показывать не только `P01 P02 P03`, но и маленькие превью детали по слоям.

Минимум:

```text
1: P01 P03 P07
2: P02 P04 P08
...
```

Лучше:

- компактный 2D-превью-силуэт сверху;
- список слоёв детали, если высота больше 1.

## Шаг 6. Не ломать генератор

После изменений проверить:

- карточка генерируется при `levels=2`, `pieceCount=3`, `comboCount=6`;
- при невозможных настройках появляется понятная ошибка;
- экспорт JSON работает;
- печать/PDF работает.

## Критерий готовности

Готово, когда в репозитории есть:

```text
data/pieces_thingiverse_6534722.json
source_stl/thingiverse_6534722/*.stl
scripts/tools для повторной конвертации
README с инструкцией
```

И генератор по умолчанию использует реальные формы из Thingiverse, а не демонстрационные.
